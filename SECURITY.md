# Security Policy

## 1. Ethical AI Research & Responsible Testing

The **llm-research-bench** repository conducts empirical research on the safety, adversarial robustness, and defensive capabilities of Small Language Models (SLMs).

To ensure ethical compliance and eliminate risks to real-world infrastructure:
- **Synthetic Test Environments Only:** All vulnerability probes, jailbreak prompts, indirect prompt injections, and CVE exploit simulations are executed exclusively within isolated local runtime environments with synthetic data and mock canaries.
- **No Exploitation of Live Targets:** Under no circumstances should test cases, datasets, or evaluators from this suite be used to attack external networks, cloud endpoints, or unauthorized systems.
- **Safe Sandboxing:** Execution of untrusted code blocks generated by models is sandboxed with strict execution timeouts, restricted AST checks, and no socket or system call permissions.

---

## 2. Reporting a Vulnerability

If you discover a security vulnerability in this project (such as an insecure evaluation harness, command injection flaw, or exposed credential):

1. **Do not create a public GitHub issue.**
2. Send a report directly to the repository maintainer (**Anderson Tavares**) via [GitHub Security Advisories](https://github.com/AndersonTavares0/llm-research-bench/security/advisories/new) or by creating a private issue if enabled.
3. Include the following details in your report:
   - Detailed description of the vulnerability.
   - Affected file, component, or workflow.
   - Minimal reproducible proof of concept (PoC).
   - Potential impact on users or systems.

---

## 3. Response and Disclosure Process

- **Acknowledgment:** Reports will be acknowledged within 48 hours.
- **Investigation:** We will evaluate the report, verify the issue, and prepare a fix on a private branch.
- **Remediation & Advisory:** A patch will be merged, and a security release will be published alongside an attribution note thanking the reporter.

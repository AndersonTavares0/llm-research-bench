# Benchmark fit for constrained local SLMs — short note / nota breve

**Research checked:** 2026-11-07. The repository was clean at `d4fd7aa` before this note. This is a source review, not a benchmark run. “Evidence” below reports what first-party dataset/framework sources state; “Recommendation” is our fit judgment. Dataset licenses are not model licenses.

## English

| Benchmark | Evidence: scope, protocol, license / distribution, contamination | Recommendation for this repo |
|---|---|---|
| **HumanEval** | OpenAI’s original set is Python function synthesis; its harness measures `pass@k` by executing generated code against tests and explicitly warns that code is untrusted and must run in a robust sandbox. The repository is deprecated/unmaintained. The source repository has an MIT license; that does not independently settle rights for every included data/test element (**dataset-specific rights not verified**). Small fixed public set: substantial memorization/contamination risk; per-model contamination is unverified. [Repo](https://github.com/openai/human-eval), [paper](https://arxiv.org/abs/2107.03374) | **Conditional, useful coding capability check** only with isolated execution, pinned harness and multiple samples for pass@k; do not run its harness unsandboxed. Small local models may fit runtime-wise, but tests/execution and contamination limit interpretation. |
| **MBPP** | Google Research describes ~1,000 entry-level Python tasks with three tests each; official test IDs 11–510 and three-shot examples 2–4. `sanitized-mbpp.json` is hand-verified subset. Repo has code and data but no dataset-specific redistribution/license conclusion was verified here—check exact file/revision and upstream rights before vendoring. Public, fixed items make memorization plausible; model-level contamination unknown. [Repo](https://github.com/google-research/google-research/tree/master/mbpp), [paper](https://arxiv.org/abs/2108.07732) | **Good practical coding complement** to HumanEval (broader/easier beginner tasks), but honor upstream split/few-shot protocol, report sanitized vs original, sandbox tests. |
| **GSM8K** | OpenAI’s archived release describes 8.5K human-authored grade-school word problems, 7.5K train/1K test, multi-step arithmetic, and `####` final-answer extraction; repository’s harness default is five-shot (local project documents its zero-shot deviation). The upstream repository identifies its release and paper but a clear dataset license was **not verified**—do not assume code license grants data redistribution rights. Fixed public test set: contamination possible, not assessed for a given model. [Repo](https://github.com/openai/grade-school-math), [paper](https://arxiv.org/abs/2110.14168) | **Strong fit** for text/math reasoning on CPU/GPU-constrained SLMs; run official test with a declared shot count and exact/flexible extraction separately. Output-format failures are distinct from reasoning failures. |
| **HotpotQA** | Original task is multi-hop QA with answer and supporting-fact supervision; `distractor` provides candidate paragraphs, while `fullwiki` involves retrieval. Official dataset repo states CC BY-SA 4.0 for data and Apache-2.0 for code. Current local sample is pinned 100-item balanced bridge/comparison validation subset, closed-context, not live retrieval; small sample and public source expose contamination risk. [Repo](https://github.com/hotpotqa/hotpot), [paper](https://arxiv.org/abs/1809.09600), [local attribution](../../data/rag/README.md) | **Useful, but narrow and relatively costly** as closed-context evidence-grounded QA. Score answer and supporting facts separately; do not describe the local subset as retrieval evaluation or population estimate. Preserve CC BY-SA attribution/share-alike obligations when redistributing derived dataset. |
| **XSTest** | First-party release: 450 English prompts, 250 safe prompts and 200 unsafe contrast prompts; classify responses as refusal/compliance. Prompts CC BY 4.0; supplied model completions retain their respective owners’ terms. [Repo](https://github.com/paul-rottger/xstest), [NAACL paper](https://aclanthology.org/2024.naacl-long.301/) | **Best lightweight safety calibration check** here: split false refusals on benign prompts from unsafe compliance, rather than one refusal rate. Small fixed prompt set, subjective/automated classification and contamination mean exploratory signal only. |
| **BIPIA** | Microsoft describes indirect prompt injection across email QA, web QA, summarization, table QA and code QA; reproduction uses seed 2023 and measures attack success rate (with a separate evaluator model defaulting to GPT-3.5). Some contexts must be fetched from source owing to licensing; project license alone does not license all constituent datasets. [Repo](https://github.com/microsoft/BIPIA), [paper](https://arxiv.org/abs/2312.14197) | **Conditional fit** for prompt-injection robustness when model is placed in a RAG/untrusted-context pipeline. Select one task, preserve official attack/evaluation protocol and legal provenance; evaluator-model/API and setup burden make full reproduction poorly suited to tiny local-only runs. |
| **AgentDojo** | First-party paper/repo define a dynamic stateful tool-use environment, with 97 tasks and 629 security cases; measures benign utility and security under injection, not just a single prompt response. Paper says MIT for code except marked third-party portions. Results depend on agent, tools, attack/defense and model interface; authors explicitly frame it as dynamic, not a static benchmark. Public cases still have contamination potential. [Repo](https://github.com/ethz-spylab/agentdojo), [NeurIPS 2024 paper](https://proceedings.neurips.cc/paper_files/paper/2024/hash/97091a5177d8dc64b1da8bf3e1f6fb54-Abstract-Datasets_and_Benchmarks_Track.html), [docs](https://agentdojo.spylab.ai/) | **Not a fit for base-model-only evaluation.** Use only if this project evaluates an actual tool-calling agent and can faithfully implement the stateful environment; report utility and security together. |
| **Local synthetic static cybersecurity v1** | Local set has four Python examples: two hand-labeled injection positives (CWE-78/89), two safe controls; no code execution. Scores exact CWE+line precision/recall/F1 and malformed outputs. The repo explicitly says no independent label adjudication, no held-out split, no model run, and not suitable for ranking/statistical inference. [Protocol](../benchmarks/offline-static-cybersecurity.md), [data](../../datasets/cybersecurity_static_triage_v1.json) | **Retain only as evaluator smoke test / exploratory qualitative probe**, not capability benchmark. Before comparative claims: independently adjudicate labels, expand and freeze a held-out set, broaden weakness and safe-code diversity, and report localization, FP/FN and malformed/refusal rates. No redistribution/license status beyond local authored synthetic data was separately audited. |

### Practical selection

For a small, defensible local suite: prioritize **GSM8K** (declared zero/few-shot protocol), **MBPP or HumanEval** (not both required; choose based on intended coding scope and sandbox), and **XSTest** for safety/refusal calibration. Add the pinned HotpotQA subset only for closed-context multi-hop evidence use. Treat BIPIA and AgentDojo as pipeline/agent evaluations, not ordinary SLM quality tests. Keep the tiny cybersecurity set explicitly exploratory. For every public fixed set, record source revision, prompt/template, decoding, evaluator version and split; exact benchmark familiarity for evaluated model checkpoints remains unverified.

## Português

**Síntese:** Para SLMs locais restritos, priorize GSM8K para raciocínio matemático, MBPP **ou** HumanEval para código (com execução isolada), e XSTest para calibrar recusas. HotpotQA é útil apenas para QA multi-hop com contexto fornecido, não busca aberta. BIPIA e AgentDojo medem robustez de pipelines com contexto não confiável/agentes e ferramentas; não são testes simples do modelo-base. O conjunto sintético local de quatro casos serve somente como teste exploratório do avaliador, não para ranking nem inferência. Fixe versões e protocolos, separe desempenho de formatação e verifique licenças dos dados antes de redistribuir; contaminação de checkpoints específicos não foi verificada.
